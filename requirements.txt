# What the build needs, pinned. The PDFs are the product and reportlab's text
# metrics are load-bearing: A-001 auto-sizes its type to the widest line it
# measures, C-101 and C-102 assert their column widths, and the title block
# width-checks every line on both page sizes. A reportlab that measures a string
# a fraction of a point differently moves drawn dimensions, so a float here is a
# silent redesign arriving on someone else's schedule.
#
# Bumping one is a deliberate change: install it, rebuild, and diff the trace
# against the previous build before committing. Built and issued on Python 3.12.4.
reportlab==4.4.9

# reportlab's C accelerator: its float formatting, ASCII85 and string widths in C instead of
# the pure-Python fallbacks reportlab uses without it -- a build about a quarter faster, and
# every process the gate starts is one. Checked before it was added (2026-09-26): every
# project's trace digest matched its trace.md5 with it loaded, and the PDFs were byte-identical
# less their timestamps. It stays a deliberate bump like reportlab's: rebuild and diff.
rl_accel==0.9.1

# arkitect/lib/export/dxf.py only. Nothing in the issued set depends on it.
